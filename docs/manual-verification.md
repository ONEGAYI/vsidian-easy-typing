## 验收口径总则：真实 IME、物理键盘与视觉观感

以下三面是本清单区别于自动化测试的核心口径，各功能域条目默认在其约束下执行：

- **真实 IME（微软拼音等）**：用系统输入法真实驱动 compositionstart → 候选更新 → 定稿（上屏）链路。关注三点：候选期间文档零修饰（无转换、无配对、无空格插入）、定稿文本只上屏一次、定稿后的规则/格式化与普通键入同结果。禁用「英文键盘直接输中文场景」替代。
- **物理键盘**：用真实按键验证键序与手感——连续击键的节奏（Mod+A 档位推进、Tab 跳转）、修饰键组合的真实时序（Ctrl+Shift+V、Ctrl+/）、长文档下按键的响应延迟是否可感知。自动化只能断言逻辑，手感与迟滞必须真键盘。
- **视觉观感**：断言「用户看到的东西」而非「逻辑发生」——占位符高亮是否可见、选区高亮跟随、设置页明暗主题对比度、浮层滚动与拖拽的视觉反馈。每轮至少在暗色与亮色主题各看一遍关键界面。

## 一、规则引擎 Input 触发（#1 / #25 / #17）

内置 20 条规则的 Input 类（五功能族：标点连击、配对、符号转换、半角转全角、引用标记），经行为链 onInput 驱动。

### A1. 标点连击转换（fw2hw 经函数表）

1. 正文空行键入两个全角句号（中文输入法下按两下句号键）。
2. 观察第二个句号落屏瞬间是否转换。

预期：`。。` 自动转为 `.`（`builtin-fw2hw-double` 经预注册函数表命中；#17 后无 CSP 降级）。光标落在 `.` 之后。

边界提示：撤销为**两步**（先撤转换、再撤键入）——平台撤销管线结构性边界，不是缺陷（见「已知边界汇总」B1）。

### A2. 行首符号转换

1. 行首键入全角 `》`；另起一行行首键入全角 `、`。

预期：`》` 转为 `> `（引用标记），`、` 转为 `/`（斜杠命令语义）。

### A3. 配对补全与跳过

1. 键入全角 `（`：预期补全为 `（）` 且光标在中间（`$0` 落配对间）。
2. 光标移到某 `（）` 对的左括号前（右侧恰为闭括号）再键入 `）`：预期重复闭符被吃掉（跳过语义），不产生 `（））`。

边界提示：`builtin-autopair-input` 的触发表**不含 `【`**（上游数据怪癖原样保留）——键入 `【` 不补全，不是缺陷（B12）。

### A4. 符号组合转换抽验

1. 键入两个反引号 `` `` ``：预期转行内代码标记（`·` 高亮语义位置）。
2. 键入 `￥￥`：预期转公式标记（块级/行内随上下文）。

### A5. 多光标仅首光标生效

1. Ctrl+Alt+Down 建两个光标，各在正文空行。
2. 两处各键入一次全角句号（共两次 `。`），观察转换与光标。

预期：仅一处发生规则转换；命中后其余光标**坍缩为单一光标**（平台 `applyAddonEdit` 语义，单光标场景无感知）。多光标下不命中时不改选区。

边界提示：多光标处理首个（最左）选区、其余不触发——上游 `asSingle().main` 的保守收窄，不是缺陷（B2）。

### A6. 遗留函数体规则装载警告

1. 规则管理页导入一条 `{"trigger":"x","replacement":"return 1;","options":"F"}` 形态的规则 JSON。
2. 观察装载期通知与该规则的命中行为。

预期：出现一次性警告通知（规则错误文案），该条规则不命中；同批其他规则不受影响。存储侧数据原样保留（UI 内改选预注册函数后可恢复可用）。

### A7. 独占组链序（规则命中则不格式化）

1. 键入 `。。`（命中 A1 规则）后立即观察本次输入是否还插入了中英空格。

预期：规则命中的输入**本次不做自动格式化**（独占组 `input-rules` 承载「一条输入至多一条规则生效」链序，复刻上游「规则命中即短路格式化」）。

## 二、规则引擎 Delete / SelectKey 触发（#9）

### A8. 联动删除

1. 光标在空 `（）` 对的 `（` 与 `）` 之间，按 Backspace。

预期：整个配对 `（）` 一起删除（`builtin-autopair-delete`）。

### A9. 选中包裹

1. 选中一段正文文字，键入全角 `《`。

预期：文字被 `《》` 配对包裹（`builtin-sel-wrap-cjk-brackets`）；键入全角引号、`【`/`¥`/`￥` 同理触发各自包裹规则。

边界提示：**IME 组合输入（拼音候选定稿）选中文本的包裹不可达**——平台对 compose 定稿补驱动的 replaced 恒 null（vsidian#399 边界），物理单键可用、IME 定稿不触发，不是缺陷（B3）。

### A10. 多选区落原生

1. 两处各选中一段文字，键入 `《`。

预期：包裹**不发生**（多选区一律不进 SelectKey 管线），回落 VSCode 原生选区替换行为。这是设计边界，不是缺陷（B2）。

## 三、Tabstop 占位符导航（#14 / #15）

### A11. 占位符替换与 Tab 跳转

1. 经规则管理页新建一条 Input 类规则：触发 `xm`，替换 `[[1]]号$0`（模板含占位符）。
2. 正文键入 `xm`：预期替换体上屏，首占位符区域呈**选区高亮**（复用平台查找「当前命中」配色），Tab 跳到 `$0` 位、Shift-Tab 回跳。

预期：Tab/Shift-Tab 在占位符组间跳转流畅；跳到末组（`$0`）后再按 Tab 恢复普通 Tab 语义（导航态收尾落穿平台链）。

### A12. 零宽占位符无可见高亮

1. 触发一条 `[[1]]/$0` 形态规则（如 A2 的 `、` 转换），观察 `$0` 位。

预期：`$0` 常为零宽（光标停位无可见 mark），只有光标无高亮块——已知边界，如人工验证觉得可辨识性不足，提 issue 评估静态竖线提示（B7）。

### A13. 撤销后导航态退出

1. 占位符导航态激活时按 Ctrl+Z 撤销替换，再按 Tab。

预期：撤销后 Tab 即普通缩进语义（导航态不重放）；重做也不恢复导航态（与上游一致）。

## 四、自动格式化（#26）

### A14. 中英空格基础链

1. 正文键入 `中文`，接着键入半角字母 `a`。

预期：`中文` 与 `a` 之间自动插入一个空格，**光标落在 `a` 之后**（词尾）。数字同理（`中文1` 出空格）。

### A15. 前缀词典抑制与越词补插

1. 连续键入 `n8n`（默认词典词条）：预期词条内部**无空格**插入。
2. 继续键入越出词条（如 `n8nx`）：预期边界处延迟补插空格。
3. 键入 `python3`：预期无空格（`python3`/`Python3` 双词条，字面词区分大小写——`Python3` 同样无空格、`pYthon3` 不在词条内会出空格，上游实现口径）。

### A16. IME 定稿走格式化

1. 微软拼音输入`你好` 定稿，紧接键入半角 `a`。

预期：定稿文本与普通键入同路径格式化（`你好 a` 间出空格）——compose 定稿经 `input.type.compose` 与普通输入共链。

### A17. 多光标不格式化

1. 两光标各在 `中文` 词后，各键入 `a`。

预期：**无格式化发生且光标不坍缩**（多光标键入不进格式化管线，族不返回计划即不占组、不改选区）——与规则族的多光标坍缩（A5）不同面，各自如实核对。

### A18. 作用域跳过

1. 分别在代码块内、frontmatter 内、表格行内键入 `中文a`。

预期：均**不格式化**（平台行为链门控排除这些上下文，B20）。

边界提示：正文里**行内公式 `$x$` 内光标与货币写法 `$100` 同行**时，整行被误判公式跳过（文本降级判定的已知近似，#5 语法树版就绪后消除）——验证时确认这是「跳过」而非「错乱」，属已知边界不是缺陷（B13）。

### A19. 粘贴不触发本次格式化

1. 复制一段含 `中文a` 的文本，在正文 Ctrl+V 粘贴。

预期：粘贴动作本身不做行格式化（粘贴识别跳过）；粘贴 500ms 窗内继续键入也不格式化。注意「粘贴时主动格式化」经行为链**结构性不可达**（B5），设置项 `autoFormatPaste` 的主动侧归 #28 命令承载。

## 五、自定义正则保护区（#27）

### A22. 设置改动即时生效

1. 修改保护区正则模板或任一开关后，**不重启**，回到编辑器继续键入。

预期：下一次键入即按新值判定（onChanged 刷新链路）。

## 六、Tab 跳出 Tabout（#7）

## 七、智能退格 Backspace（#8）

### A26. 顶级空列表项清除

1. 光标在 `- ` 空项行尾按 Backspace：预期清空列表标记留空行。
2. 再按一次：预期空行合并到上一行（上游净增量，平台 stripListLayer 只清不合并）。

### A27. 空引用行联降

1. `> ` 空引用行尾按 Backspace：预期降一级（`> > ` → `> ` 紧凑形态）；顶级 `> ` 清为空行。
2. 紧凑嵌套 `>>` 空行退格联降。

边界提示：层间带空格的 `> > ` **不命中**（上游正则口径），退格落平台逐层剥除——结果仍正确，属边界不是缺陷（B14）。

### A28. 让位面（平台接手，非本组件行为）

1. 缩进空列表项（行首空白）、空任务项 `- [ ]`、引用内列表 `> - ` 三场景分别退格。

预期：由**平台** stripListLayer 处理（升一级/清整段标记/引用内清层）——本组件有意让位（平台语法树语义更准，B10）。核对要点是结果正确且无双跳（一次退格只发生一次清除）。

## 八、渐进选择 Mod+A 与「选择当前块」（#11）

预期：选区按 段落 → 引用/列表块 → 全文 档位逐级扩大；节奏连贯、选区高亮即时跟随；末档后回到平台原生全选。

### A30. 失配透传

1. 分别在代码围栏内、公式块内、frontmatter 内按 Mod+A。

预期：落穿为**原生全选**（分支失配透传，键位永不失效）。

### A31. 设置运行时翻转

1. 关闭 `enhanceModA` 回编辑器按 Mod+A：预期与原生全选**无差别**；重新开启后下一次按键即恢复渐进。

## 九、智能粘贴 SmartPaste 与纯文本粘贴（#12）

### A34. 续接矩阵抽验

逐场景：光标在列表项/引用行行尾，分别粘贴——

1. 单行纯文本（无前缀）：预期并入当前项（不重复加前缀）。
2. 多行纯文本：预期逐行加前缀续接。
3. 粘贴内容本身是列表（`- a`）：预期首项并入、后续项保留自身标记。
4. 带续行的列表（次行缩进）：预期续行对齐缩进。
5. 目标行 `>nospace`（无尾随空格）：预期续接前缀归一为 `> `，不改写已有行内文本。

### A35. 纯文本粘贴命令

### A36. 撤销与多光标

1. 续接粘贴后按一次 Ctrl+Z：预期**单笔整体回退**（续接是一次计划）。
2. 两光标粘贴 2 行文本：预期原生行分配正常，不被续接干扰（多光标不续接，明确边界）。

### A37. 让位面

预期：三个让位场景全部由平台接手、结果正确，本组件不吞事件不二次加工。

## 历轮执行记录落档约定

- **记录表结构**：轮次 / 日期 / 执行人 / 环境摘要（VSCode 版本 + vsidian 基线 + VSIX）/ 覆盖范围（A 编号区间）/ 结果（通过 / 未过 / 部分 / 阻塞）/ 备注（复现证据：截图、日志、操作录制说明）。
- **归档位置**：全部落本文档——轮级摘要追加至「当前执行记录」首表，逐项结果填入第二表；单轮叙述较长时在首表备注列内链新起小节（`## 历轮执行记录：R<N>`）置于「已知边界汇总」节之前，正文写细节。
- **未过项跟踪**：确认缺陷（含「不是缺陷」清单之外的新行为分歧）开 GitHub issue 跟踪，正文引用 issue 号；属平台侧的问题转 vsidian 主仓提案并在本仓 issue 互链。既有「不是缺陷」项（B 编号）验证通过即勾选，不另开票。
- **口径继承**：每轮执行沿用「验收口径总则」三面约束；矩阵轮（vsidian 升级 / VSIX 变更）须在矩阵表追加一行并在备注注明 vendor 快照核对结果（`npm run vendor:check`）。
