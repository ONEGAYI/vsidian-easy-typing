## 验收口径总则：真实 IME、物理键盘与视觉观感

以下三面是本清单区别于自动化测试的核心口径，各功能域条目默认在其约束下执行：

- **真实 IME（微软拼音等）**：用系统输入法真实驱动 compositionstart → 候选更新 → 定稿（上屏）链路。关注三点：候选期间文档零修饰（无转换、无配对、无空格插入）、定稿文本只上屏一次、定稿后的规则/格式化与普通键入同结果。禁用「英文键盘直接输中文场景」替代。
- **物理键盘**：用真实按键验证键序与手感——连续击键的节奏（Mod+A 档位推进、Tab 跳转）、修饰键组合的真实时序（Ctrl+Shift+V、Ctrl+/）、长文档下按键的响应延迟是否可感知。自动化只能断言逻辑，手感与迟滞必须真键盘。
- **视觉观感**：断言「用户看到的东西」而非「逻辑发生」——占位符高亮是否可见、选区高亮跟随、设置页明暗主题对比度、浮层滚动与拖拽的视觉反馈。每轮至少在暗色与亮色主题各看一遍关键界面。

## 一、规则引擎 Input 触发（#1 / #25 / #17）

内置 20 条规则的 Input 类（五功能族：标点连击、配对、符号转换、半角转全角、引用标记），经行为链 onInput 驱动。

### A1. 标点连击转换（fw2hw 经函数表）

1. 正文空行键入两个全角句号（中文输入法下按两下句号键）。
2. 观察第二个句号落屏瞬间是否转换。

预期：`。。` 自动转为 `.`（`builtin-fw2hw-double` 经预注册函数表命中；#17 后无 CSP 降级）。光标落在 `.` 之后。

边界提示：撤销为**两步**（先撤转换、再撤键入）——平台撤销管线结构性边界，不是缺陷（见「已知边界汇总」B1）。

### A2. 行首符号转换

1. 行首键入全角 `》`；另起一行行首键入全角 `、`。

预期：`》` 转为 `> `（引用标记），`、` 转为 `/`（斜杠命令语义）。

### A3. 配对补全与跳过

1. 键入全角 `（`：预期补全为 `（）` 且光标在中间（`$0` 落配对间）。
2. 光标移到某 `（）` 对的左括号前（右侧恰为闭括号）再键入 `）`：预期重复闭符被吃掉（跳过语义），不产生 `（））`。

边界提示：`builtin-autopair-input` 的触发表**不含 `【`**（上游数据怪癖原样保留）——键入 `【` 不补全，不是缺陷（B12）。

### A4. 符号组合转换抽验

1. 键入两个反引号 `` `` ``：预期转行内代码标记（`·` 高亮语义位置）。
2. 键入 `￥￥`：预期转公式标记（块级/行内随上下文）。

### A5. 多光标仅首光标生效

1. Ctrl+Alt+Down 建两个光标，各在正文空行。
2. 两处各键入一次全角句号（共两次 `。`），观察转换与光标。

预期：仅一处发生规则转换；命中后其余光标**坍缩为单一光标**（平台 `applyAddonEdit` 语义，单光标场景无感知）。多光标下不命中时不改选区。

边界提示：多光标处理首个（最左）选区、其余不触发——上游 `asSingle().main` 的保守收窄，不是缺陷（B2）。

### A6. 遗留函数体规则装载警告

1. 规则管理页导入一条 `{"trigger":"x","replacement":"return 1;","options":"F"}` 形态的规则 JSON。
2. 观察装载期通知与该规则的命中行为。

预期：出现一次性警告通知（规则错误文案），该条规则不命中；同批其他规则不受影响。存储侧数据原样保留（UI 内改选预注册函数后可恢复可用）。

### A7. 独占组链序（规则命中则不格式化）

1. 键入 `。。`（命中 A1 规则）后立即观察本次输入是否还插入了中英空格。

预期：规则命中的输入**本次不做自动格式化**（独占组 `input-rules` 承载「一条输入至多一条规则生效」链序，复刻上游「规则命中即短路格式化」）。

## 二、规则引擎 Delete / SelectKey 触发（#9）

### A8. 联动删除

1. 光标在空 `（）` 对的 `（` 与 `）` 之间，按 Backspace。

预期：整个配对 `（）` 一起删除（`builtin-autopair-delete`）。

### A9. 选中包裹

1. 选中一段正文文字，键入全角 `《`。

预期：文字被 `《》` 配对包裹（`builtin-sel-wrap-cjk-brackets`）；键入全角引号、`【`/`¥`/`￥` 同理触发各自包裹规则。

边界提示：**IME 组合输入（拼音候选定稿）选中文本的包裹不可达**——平台对 compose 定稿补驱动的 replaced 恒 null（vsidian#399 边界），物理单键可用、IME 定稿不触发，不是缺陷（B3）。

### A10. 多选区落原生

1. 两处各选中一段文字，键入 `《`。

预期：包裹**不发生**（多选区一律不进 SelectKey 管线），回落 VSCode 原生选区替换行为。这是设计边界，不是缺陷（B2）。

### A72. 非 All 用户规则的作用域判定坐标（#37）

1. 将 `[ {"trigger":"zz","replacement":"ZZ","options":"df"} ]` 保存为 JSON 文件，经规则管理页「导入」上传（顶层数组内仅一条 Formula 作用域的 Delete 类规则）。确认平台「行为冲突管理」中的「成对结构联动删除」（`06-delete-rules`）已启用，暂停其他用户规则，测试文本不落在自定义正则保护区。
2. 新建测试文档，在 Live 正文第一行准备源文本 `$azzb$ tail`（非代码块、frontmatter 或表格格区）。光标移入行内公式源文本，**仅选中 `zz`** 后按 Backspace，保留两侧的 `a`、`b`、`$` 与尾部 ` tail`。
3. 对照：将第一行重置为非公式正文 `azzb tail`，同样仅选中 `zz` 后按 Backspace。

预期：公式内删除命中该 Formula 限定规则，结果为 `$aZZb$ tail`；非公式对照不命中，结果为 `ab tail`。

判别点：正例的原生删除后快照为 `$ab$ tail`；事务前虚拟光标为位置 4，换算后的删除位置为 2（第一行从 0 计数）。实时位置 2 在公式内，旧实现误用位置 4 则落在公式后的空格，漏判为 Text，结果停在 `$ab$ tail`。必须保留 `b`、闭合 `$` 与尾部文本，才能区分 #37 的删除坐标修复。作用域判定使用删除后的实时文档与换算位置，见 [rule-engine.md「事务前重建与坐标换算」](specs/rule-engine.md#事务前重建与坐标换算核心设计)。

边界提示：围栏代码块与行内代码上下文会被平台先行门控，不驱动此规则；不能用代码区正例验收坐标修复（B20）。本项仍为「待验证」，自动化探针不计入人工执行记录。

## 三、Tabstop 占位符导航（#14 / #15）

### A11. 占位符替换与 Tab 跳转

1. 经规则管理页新建一条 Input 类规则：触发 `xm`，替换 `[[1]]号$0`（模板含占位符）。
2. 正文键入 `xm`：预期替换体上屏，首占位符区域呈**选区高亮**（复用平台查找「当前命中」配色），Tab 跳到 `$0` 位、Shift-Tab 回跳。

预期：Tab/Shift-Tab 在占位符组间跳转流畅；跳到末组（`$0`）后再按 Tab 恢复普通 Tab 语义（导航态收尾落穿平台链）。

### A12. 零宽占位符无可见高亮

1. 触发一条 `[[1]]/$0` 形态规则（如 A2 的 `、` 转换），观察 `$0` 位。

预期：`$0` 常为零宽（光标停位无可见 mark），只有光标无高亮块——已知边界，如人工验证觉得可辨识性不足，提 issue 评估静态竖线提示（B7）。

### A13. 撤销后导航态退出

1. 占位符导航态激活时按 Ctrl+Z 撤销替换，再按 Tab。

预期：撤销后 Tab 即普通缩进语义（导航态不重放）；重做也不恢复导航态（与上游一致）。

## 四、自动格式化（#26）

### A14. 中英空格基础链

1. 正文键入 `中文`，接着键入半角字母 `a`。

预期：`中文` 与 `a` 之间自动插入一个空格，**光标落在 `a` 之后**（词尾）。数字同理（`中文1` 出空格）。

### A15. 前缀词典抑制与越词补插

1. 连续键入 `n8n`（默认词典词条）：预期词条内部**无空格**插入。
2. 继续键入越出词条（如 `n8nx`）：预期边界处延迟补插空格。
3. 键入 `python3`：预期无空格（`python3`/`Python3` 双词条，字面词区分大小写——`Python3` 同样无空格、`pYthon3` 不在词条内会出空格，上游实现口径）。

### A16. IME 定稿走格式化

1. 微软拼音输入`你好` 定稿，紧接键入半角 `a`。

预期：定稿文本与普通键入同路径格式化（`你好 a` 间出空格）——compose 定稿经 `input.type.compose` 与普通输入共链。

### A17. 多光标不格式化

1. 两光标各在 `中文` 词后，各键入 `a`。

预期：**无格式化发生且光标不坍缩**（多光标键入不进格式化管线，族不返回计划即不占组、不改选区）——与规则族的多光标坍缩（A5）不同面，各自如实核对。

### A18. 作用域跳过与语法树判定（#5）

1. 分别在代码块内、frontmatter 内、表格行内键入 `中文a`。

预期：均**不格式化**（平台行为链门控排除这些上下文，B20）。

2. 行内公式内光标键入：行内 `中文$x中文a$` 光标落在 `$...$` 内键入 `b`。

预期：该行**不格式化**（#5 树版位置级作用域门控——上游全行校验会格式化该行其他分区，差异如实保留，B13）。

3. 货币行键入：`价格 $100 与 $200` 光标在货币之间键入 `a`。

预期：**照常格式化**（#5 后货币 `$` 误判已消除——平台判定链 `$` 配对语义；#25 降级版曾误判 Formula 跳过整行）。

4. 链接内 code span 键入：`[[笔记|`代码`]]` 光标在反引号内键入 `a`。

预期：**照常格式化**（链接区段排除——上游 `!contains('link')` 语义，#5 链接内 code span 判 Text；#25 降级版曾按行内代码跳过整行）。

边界提示：反引号内直接写 `[[双链]]`（`` `[[双链]]` ``）时被链接正则圈走判链接（上游树版判 code）——已知差异（syntax-line-types.md「已知口径差异」），该处键入行为以链接语义为准。

### A19. 粘贴不触发本次格式化

1. 复制一段含 `中文a` 的文本，在正文 Ctrl+V 粘贴。

预期：粘贴动作本身不做行格式化（粘贴识别跳过）；粘贴 500ms 窗内继续键入也不格式化。注意「粘贴时主动格式化」经行为链**结构性不可达**（B5），设置项 `autoFormatPaste` 的主动侧归 #28 命令承载。

## 五、自定义正则保护区（#27）

### A20. 保护区格式化豁免

1. 正文键入 `{{中文a}}`（默认模板 `{{...}}` 在保护区内）。

预期：`}}` 内键入 `a` **无空格插入**（保护区生效）。

2. 设置页关闭 `userDefinedRegSwitch`（保护区开关），重复步骤 1。

预期：同场景恢复格式化（出空格）。

### A21. 用户规则尊重保护区

1. 设置页同时开启 `userDefinedRegSwitch` 与 `userRulesRespectUserDefinedRegexBlocks`（后者默认关）。
2. 键入 `{{。。}}`：预期 `}}` 内标点折叠**不触发**。
3. 关闭 `userRulesRespectUserDefinedRegexBlocks` 再试：预期恢复触发。

## 十八、行内代码/公式/链接间距三档（#4）

行内元素（代码/公式/双链/Markdown 链接）与相邻文本间的空格策略：每类元素独立三档（`inlineCodeSpaceMode` / `inlineFormulaSpaceMode` / `inlineLinkSpaceMode`：none 永不补 / soft 邻侧无空格才补 / strict 总是保证空格——邻侧已有标点类「软空格状态」也补足），链接另有智能空格开关（`inlineLinkSmartSpace`，默认开）。设置入口在 Vsidian 设置「附加组件」分页本组件条目。

**驱动口径**：以下场景的键入点一律落在 **text 分区**（把行内元素全部键入完成后，光标移到最后一个元素右侧，再键入一个中文字符触发）——光标在行内公式/代码标记内部键入时整行不格式化（B13，#5 位置级作用域）。已手写好的整行可改用 #28「格式化文档/选区重排」命令驱动（命令链消费同一组设置，见 A67）。

### A64. 行内代码与公式的三档间距

1. 默认档（soft）：正文键入 `中文`，接键入 `` `a` ``（行内代码），光标移到代码右侧再键入 `中`。

   预期：键入落屏时行变为 `中文 \`a\` 中`——text 与代码之间各出现一个空格，光标在新键入字符之后。公式同法（`$x$`）验证 `inlineFormulaSpaceMode` 默认档：`中文 $x$ 中`。

2. 设置页改 `inlineCodeSpaceMode = none` 后重复步骤 1（改设置后稍候 3 秒或连续键入几次再核对，见 A22 节流口径）。

   预期：不再补空格（`中文\`a\`中` 保持原样）。

3. 改 `inlineCodeSpaceMode = strict`，构造 text 侧带全角标点的形态：键入 `中文，` 接 `` `a` ``，光标移到代码右侧键入 `中`。

   预期：标点后**仍补空格**（`中文， \`a\` 中`）——strict 档连「软空格状态」（全角标点）也补足；对照 soft 档下同形态不补（`中文，\`a\`` 尾随元素时无变更），这是 strict 档的独有行为。

边界提示：撤销口径同 B1（空格修饰与键入分离，Ctrl+Z 先撤空格再撤键入）。

### A65. 链接三档与智能空格开关

1. 默认（智能开 + soft 档）：键入 `中文[[笔记]]中文`（键入点在尾部 text）。

   预期：`中文 [[笔记]] 中文`——中英文侧与双链之间出空格；mdlink（`[标题](地址)`）同法同结果。

2. 智能空格的边界形态（保持默认设置）：

   1. 别名以汉字开头：`中文[[a|别名]]中文` → 预期**不插**空格（两侧显示字符均为汉字）。
   2. 链接尾显示字符为全角标点：`中文[[a|别名，]]中文` → 预期不插。
   3. 已有空格回退删除：`中文 [[别名]]中文` → 预期空格被**删**（汉字_空格_汉字 智能收紧为无空格）。
   4. 空链接：`中文[[]]中文` → 预期不动。

3. 关闭 `inlineLinkSmartSpace` 后逐档验证：none 档 `中文[[a]]中文` 不插；soft 档同形态插（`中文 [[a]] 中文`）；strict 档 `中文，[[a]]中文` 标点后仍补。

边界提示：**strict 档优先于智能**——智能开 + strict 档时 `中文[[别名]]`（汉字贴链接，智能本会不插）仍补空格为 `中文 [[别名]]`，与智能的「汉字间不插」并存不矛盾（档位判定在前），不是缺陷。

### A66. 非 text 分区直接相邻与多元素混排

1. 键入 `中文\`a\`$x$中文`（代码与公式直接相邻，键入点在尾部 text）。

   预期：三处边界各出一个空格（`中文 \`a\` $x$ 中`），包括代码与公式**之间**（任一侧档位非 none 即插）。

2. 键入 `中文\`a\`[[b]]中文`（代码与双链直接相邻）。

   预期：同样三处空格（`中文 \`a\` [[b]] 中`）。

### A67. 命令重排驱动与设置即时生效

1. 不经键入触发：手写（或粘贴）一整行 `中文\`a\`中文`，执行 #28「格式化文档」或选中该行执行选区重排命令。

   预期：与键入路径同结果（`中文 \`a\` 中文`）——命令链消费同一组间距设置。

2. 改任一档位/智能开关后**不重启**，回编辑器用步骤 1 的命令重排同一行核对：结果随新设置变化（onChanged 刷新，3s 节流窗，同 A22 口径）。

## 十九、代码块编辑增强 BetterCodeEdit（#10）

> 三项接入（Mod+A 三态选择、块内多行粘贴对齐、缩进代码块删除优化）共享 `betterCodeEdit` 设置（默认开，与 #11 的 enhanceModA 相互独立）；三项跳过项（块内 Tab 缩进、Enter 保持缩进、行内代码 Tab 跳出）由 vsidian 内核承载，A71 为口径差异感知项。内核核对结论、实施决策点与选层理由见 [docs/specs/better-code-edit.md](specs/better-code-edit.md)。

### A68. Mod+A 三态档位推进

1. 确认设置页 `betterCodeEdit` 开启；#11 的 `enhanceModA` 开关任意（两开关独立，分别验证一开一关组合）。
2. 光标落在多行代码块内容区按 Mod+A：预期选中**块内容**（首内容行行首 → 末内容行行尾，不含围栏行）。
3. 再按 Mod+A：预期升档为**整块**（开栏围栏起点 → 闭栏行尾）。
4. 第三次按 Mod+A：预期落穿为平台**全文全选**（三态链闭环）。
5. 表格单元格内按 Mod+A，预期随 `enhanceModA` 组合分叉——**关闭**时平台格内选格优先（表格非代码块，本组件三态不触发）；**开启**时 #11 按文本档位接管表格行（平台 table kind 投影为 text，#11 抢先层先于平台表格键位：首按规整当前行、再按升段块——#11 既有语义，非本组件行为）。
6. 空代码块（开闭栏紧邻）内连续按 Mod+A：预期一次选整块、二次落穿全文全选（上游为重复派发同选区，本仓口径闭环，B22）。

### A69. 块内多行粘贴对齐

1. 光标在列表下缩进代码块（缩进 2 列）内容中，粘贴两行无缩进文本：预期首行原样插入、第二行行首补 2 空格对齐块缩进；一次撤销整体回退。
2. 粘贴两行带共同缩进的文本：预期剥共同缩进后再按块缩进重排；粘贴文本首行无缩进时，其余行自身缩进保留并叠加块缩进（上游实然，B22）。
3. 粘贴含 tab 的多行文本：预期行内 tab 替换为 2 空格（固定口径，非宿主 tab 设置——实施决策点）。
4. 单行文本粘贴 / 粘贴点带选区：预期不接管，走原生粘贴语义。
5. 代码块行尾粘贴**多行**文本：预期本组件对齐接管（代码块判定先于 SmartPaste，不被列表/引用续接抢走）；同文本粘贴在块外列表行尾则走 SmartPaste 续接。**单行**文本不在此列——光标在代码块内的**字面列表/引用行**（如围栏内写的列表示例）行尾粘贴单行文本时 #12 续接仍生效（续接判定只看光标行形态，上游 SmartPaste 同样无代码块排除，实然同形）。

### A70. 缩进代码块 Backspace 两分支与 #8 让位共存

1. 光标在缩进块内容行首列（缩进边界列）按 Backspace：预期连换行带缩进一起删（当前行并入上一行，不残留缩进空白）。
2. 选中「缩进 + 首个内容字符」（跨边界选区）按 Backspace：预期只删内容字符，缩进列保留。
3. 顶格代码块内同位置操作：预期完全不接管（普通删字符）——对照项。
4. 缩进空列表项 / 空引用行按 Backspace：预期 #8 先接管（同层注册序在前），本组件不干扰——让位共存核对。

### A71. 跳过项口径差异感知（口径差异感知，非缺陷）

1. 块内 Tab：预期整行加 2 空格（vsidian #120 整行制；上游为光标位插入一个 tab 字符）。
2. 块内 Enter：预期保持缩进且空白按 2 空格列规整（CM6 默认行为；上游逐字复制原行前缀）。
3. 行内代码内 Tab：预期两步越出（先贴闭合反引号左侧、再越出——vsidian #125；上游未闭合反引号直接跳行尾）。

预期：三个跳过项由 vsidian 内核承载，与上游口径存在既定差异（B21）；若观感不符预期，属内核口径问题（#120 / CM6 defaultKeymap / #125），不由本组件另起炉灶（会破坏三段链整行制一致性）。

## 二十、严格换行三模式补偿（#30）

前置：宿主 Vsidian「阅读宽松换行」设置关闭（严格渲染，默认态）且本组件设置页开启 `strictModeEnter`（默认关）；模式键 `strictLineMode`（`enter_twice` / `two_space` / `mix_mode`）。双门任一关闭时本节全部项预期为「无补偿、平台普通换行」。

### A73. Enter 三模式键序（正文与引用行）

1. `enter_twice`：段尾（下一行为空行）正文行按一次 Enter——预期插入空行分段（源文 `\n\n`，光标落新行行首）。
2. `two_space`：同位置按 Enter——预期行尾出现两空格后换行（源文 `  \n`）；行尾已有两空格时不重复（只换行）。
3. `mix_mode`：正文行为 `enter_twice` 形态；引用行（`> 文字`）为 `two_space` 形态（两空格 + 换行 + `> ` 前缀）；`enter_twice` 下引用行为双行引用（换行 + `> ` + 换行 + `> `）。
4. 阅读视图核对：补偿后的换行在阅读模式可见（分段或硬换行）——这是补偿的目的语义。

### A74. 边界门槛与落穿面

1. 段中边界：`enter_twice`/`mix_mode` 模式下光标在**下一行非空白**的行内按 Enter——预期不补偿（平台普通换行，不插空行）；`two_space` 同场景仍补偿（两空格不改段结构）。
2. 空白行与行首：空白行按 Enter、任意行**行首**（列 0）按 Enter——预期不补偿。
3. 纯引用前缀行（`> ` 后无内容）与 callout 标题行（`> [!note] …`）——预期不补偿。
4. 列表行（`- a`、`1. a`、`- [ ] a`）按 Enter——预期不补偿（平台续行链处理）。
5. 顶格代码块闭栏行行尾：`enter_twice` 且下一行为空行——预期插空行（`\n\n`）；下一行非空白时不补偿。
6. 折叠标题行按 Enter——预期折叠层接管（A38 行为不变，补偿层让位）。

### A75. Mod+Enter 严格形态（双平台）

1. Windows/Linux 按 Ctrl+Enter、macOS 按 Cmd+Enter（同键位双平台形态）。
2. 正文行行尾：`enter_twice`/`mix_mode` 预期下方插**空行**再新行（`\n\n` 起始）；`two_space` 预期行尾两空格 + 换行。
3. 引用行行尾：`enter_twice` 双行引用、其余两空格 + `> ` 前缀；列表行行尾不补偿（前缀延续照旧）；代码块/公式块内不补偿（普通换行 + 缩进延续）。
4. 撤销：Ctrl+Z 单笔回退整次改写（含两空格/双换行与光标）。

### A76. 双门控翻转与热更跟随

1. 组件门：设置页关闭 `strictModeEnter` 后回到编辑器按 Enter/Mod+Enter——预期立即恢复平台行为（焦点回归刷新生效）。
2. 宿主门：Vsidian 设置开启「阅读宽松换行」后**不重开面板**，直接回编辑器按 Enter——预期补偿立即停用（拉取式跟随热更）；关闭该设置后补偿恢复。
3. `strictLineMode` 运行时切换（如 `enter_twice` → `two_space`）——预期回到编辑器后按键即按新模式（无需重开）。
