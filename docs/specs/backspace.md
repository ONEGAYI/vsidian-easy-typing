# BetterBackspace——空列表/引用清除与重编号（工单 #8）

> 上游 easy-typing-obsidian 的智能退格移植：空列表项/空引用行上按退格
> 一键清除结构前缀（而非逐字符删除），有序列表空项删除后同层后续项
> 自动重编号；空引用行按层级降级或与上一行合并。领域词汇见
> [CONTEXT.md](../../CONTEXT.md)「BetterBackspace」条。

### 语义要点（与上游逐一对齐）

- **入口门槛**：折叠光标且恰在**行尾**；行内容恰为空项前缀（列表标记
  后**恰好一个空格**；引用为连续 `>` 串 + 可选一个尾空格）。
- **空列表项**：上一行是列表项（标记 + 空白即认）→ 删当前行（连换行）
  合并到上一行末尾；否则清空当前行内容（留空行）。
- **重编号**：当前行有序时，同缩进的后续有序项**恰好连续**则各减一、
  逐项顺延；跳号、缩进不同、遇非有序行即停（跨层不重排）。无序项
  删除不触发。
- **空引用行**：多级 + 上一行是完全相同的空引用行（同缩进同层级）→
  两行**同时**降一级（联降，光标在新第二行末尾）；多级其他 → 当前行
  降一级；单级 + 上一行是引用 → 删当前行合并；否则清空当前行内容。
- 变更**单笔事务**派发，一次撤销整体回退（上游同；事务形态对齐平台
  stripListLayer 惯例）。

### 与上游的差异

- **有序 `1)` 分隔符**（票面显式扩展，上游仅 `1.`）：空项判定、上一行
  判定与重编号扫描均纳入；重编号保留原分隔符与原空白字符（上游替换
  串写死 `. `，gap 为 tab 时会被改写——本仓只改号）。
- **任务项（`- [ ]`/`- [x]`）**：纳入前缀解析（票面范围 1），行为层
  不接管——让位平台（见「冲突核对」第 3 条）。上游空项正则本不含
  任务形态。空任务项的尾空格对齐引用分支取可选语义（`- [ ]` 与
  `- [ ] ` 均算空任务项）。
- **多级引用降级保留前导缩进**：上游联降分支带缩进、单行降级分支丢
  缩进，属上游内部不一致——本仓取联降语义统一（`  >> ` → `  > `）。
- **多选区显式透传**：上游只检查 main 折叠（多光标下派发会丢副光标），
  本仓防御性收紧为整体透传。
- **userEvent / scrollIntoView**：上游用自定义 `EasyTyping.handleBackspace`
  且不滚动；本仓对齐平台惯例用 `delete.backward` + `scrollIntoView: true`
  （撤销归类正确、平台行为链 delete 白名单可观察、合并分支光标跨行不
  滚动易脱视）。
- **IME 组合中与只读状态不接管**（上游无此判定；平台 listEditing 同
  口径）。
- 设置门控：上游读 `settings.BetterBackspace`；本组件设置面未建（随
  设置票落地），当前恒开，接线点在 `src/page-editor.ts`（关闭 = 不
  注册本 keymap）。

## 平台映射

- **实验 cm6 keymap**（清单 `experimental.cm6: "^1.1.0"` 保持 `^`）：
  `cm6.state.Prec.high(cm6.view.keymap.of([{ key: 'Backspace', run:
  betterBackspaceCommand }]))` 经 `sdk.registerExtension` 挂载。CM6
  运行时值只经实验入口取得（构建桥双防线拒绝直接 `import
  @codemirror/*` 值）。
- **层归属**（票面评论定案）：**抢先层**（Prec.high）——按 #402 四层
  契约可替代平台键位，先于平台普通情境链尝试；命中 `return true`
  接管，其余 `return false` 落穿。与 #7 Tabout 的**落穿层**不同——
  Backspace 无 Tab 式平台恒接管链，抢先层直接可达。
- 性能：决策先做零开销单行门槛（行尾 + 前缀解析 + 让位形态），命中
  才逐行迭代构造行数组（`iterLines`，免全文复制）驱动纯逻辑——常规
  退格主路径不付拆行开销，大文档命中场景的拆行成本仅在空项退格时发生。
- 实验层 keymap 不进平台统一快捷键管理（用户关闭 = 停用本组件；功能
  粒度开关随本插件设置票接线）。

## 平台 Backspace 冲突核对（票面要求的核对结论）

> 核对基线：vsidian origin/main 的 `src/webview/listEditing.ts`、
> `src/webview/symbolAutocomplete.ts`、`src/webview/tableEditing.ts`、
> `src/webview/liveInstance.ts` 装配序列、`src/shared/listPrefix.ts`
> （#119/#120/#123；vendor 快照锚定提交）。

平台 Backspace 情境链（均无 Prec 普通槽，按装配序正序尝试）：
**symbolAutocomplete 删自动空对（deleteAutoclosePair）→ listEditing
退格清层（stripListLayer）→ tableEditing 表格删除族 → defaultKeymap**。
四层契约下保留键闸（Prec.highest）只有撤销/重做——**抢先层对
Backspace 首先可达**，无 Tab 落穿层那种「平台恒接管链先消费」问题。
逐项核对：

1. **重叠面与平台 `stripListLayer`（#119）**：其命中条件是折叠光标
   **紧邻前缀右端**（正文起点）——空项场景下前缀右端即行尾，与上游
   「光标在行尾」重合，双方对同场景都能命中。行为对比：
   - 平台「顶级一次清整段标记（clear）」与上游「清空当前行内容」
     **结果等价**（均留空行）——此面接管不改变结果；
   - 平台**无**「合并到上一行」（留空行 vs 上游删行合并）、**无**
     「有序重编号」、**无**「多级引用联降/与上一行合并」——此三面是
     本组件接管平台的**净增量**；
   - 平台「嵌套项先升一级（dedent）」按**语法树**取父项标记列——本
     组件无树（experimental.cm6.language 在 live 恒为空树，见 API 速查
     §7），上游文本近似（上一行匹配列表前缀即合并）在嵌套场景会误删
     子项行丢失缩进。**此面让位平台**。
2. **让位面（本组件 `return false`，平台接手）**：
   - **缩进空列表项**（行首空白非空）：平台树判 dedent 升级或 clear
     （GFM 顶级缩进由树说清）——语义比上游合并更准；
   - **空任务项**：平台 clear 把「任务标记与列表标记作为一个单元」
     一次清整段——上游正则本不命中任务形态，让位即补齐票面「清除
     整段前缀」语义且不双重接管；
   - **引用内列表**（`> - `）：上游正则不命中 `>` 开头行，本组件自然
     透传，平台处理。
3. **接管面（本组件先于平台命中）**：顶级空列表项（合并/清行 + 重
   编号）与空引用行（联降/降级/合并/清行）。接管面之外的平台分支
   （光标在前缀中间、非空项、表格/代码/公式/frontmatter 上下文、
   多光标、IME 组合中）本组件一律未命中或防御性透传——平台链照旧，
   回归无损。
4. **与 symbolAutocomplete 删空对天然互斥**：其接管面是「光标紧贴刚
   自动补全的配对符」，此时行尾字符是配对符而非空格/`>`，不满足本
   组件空项形态——两链无重叠场景，抢先层不遮蔽删空对。
5. **与 tableEditing 删除族**：表格行（`| a |`）非空项形态，本组件
   不命中；表格上下文里的退格全部落穿平台。

**结论**：哪层可达——抢先层（Prec.high）对 Backspace 全场景可达（先
于平台情境链）；让位面——嵌套空项、空任务项、引用内列表三处有意让
位平台（平台树语义更准或上游本不覆盖），其余接管面为平台没有的净
增量能力。平台 `stripListLayer` 在让位面与非命中面继续承担，**无双重
接管**（keymap 命中即止，本组件 `return true` 后平台链不再运行）。

## 已知边界

- 引用嵌套命中形态是**紧凑 `>` 串**（`>>`、`>>>`）；层间带空格的
  `> > ` 上游正则即不命中（本仓保持），其退格落穿平台 stripListLayer
  逐层剥除（`> > ` → `> `）。
- 重编号只做同层后续项顺延（上游语义），不做跨层全局重排；跨层编号
  （如上级列表中间嵌子列表后的父层编号）不修正。
- 空项判定与树无关（文本形态学）：`- - ` 这类伪前缀行（列表标记后又
  是标记）在上游按空列表项命中，本仓保持——树合法性核验是平台
  stripListLayer 的职责，让位面已覆盖真嵌套场景。
- 嵌套让位的文本判定（行首缩进非空）比平台树判定保守：GFM 里缩进
  不足 4 空格的项可能仍是顶级（树会判 clear），此场景让位后由平台
  处理，结果仍正确（清整段前缀），只是走了平台分支。
- 浏览器真实键盘端到端（真实 Backspace 键序列、撤销单笔回退）归
  #21 人工验证清单。
